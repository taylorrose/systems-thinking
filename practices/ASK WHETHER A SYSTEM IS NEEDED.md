# ASK WHETHER A SYSTEM IS NEEDED

Start with [[axioms/AVOID UNNECESSARY SYSTEMS (SYSTEMS SHOULD NOT BE MULTIPLIED UNNECESSARILY)|no system as the default]]. Test, in order, whether you can [[axioms/DO IT WITHOUT A NEW SYSTEM IF YOU CAN|act without creating one]], [[axioms/DO IT WITH AN EXISTING SYSTEM IF YOU CAN|use an existing system]], or [[axioms/DO IT WITH A SMALL SYSTEM IF YOU CAN|use a small one]]. Before automating, admit that [[axioms/SOME THINGS JUST CAN’T BE DONE WELL BY A SYSTEM|some goals resist systems]] and [[axioms/CHOOSE YOUR SYSTEMS WITH CARE|choose only after those gates]].

Do not disturb demonstrated function. Apply [[axioms/IF A SYSTEM IS WORKING, LEAVE IT ALONE. DON’T CHANGE ANYTHING|leave working operation alone]]. If a large system does not work, accept that [[axioms/BIG SYSTEMS EITHER WORK ON THEIR OWN OR THEY DON’T. IF THEY DON’T, YOU CAN’T MAKE THEM|force will not make it work]], [[axioms/PUSHING ON THE SYSTEM DOESN’T HELP|pressure is not repair]], [[axioms/EVEN TRYING TO BE HELPFUL IS A DELICATE AND DANGEROUS UNDERTAKING|help can disrupt function]], and [[axioms/ADDING MANPOWER TO A LATE SOFTWARE PROJECT MAKES IT LATER|added coordination can deepen delay]].

If a new capability remains necessary, establish the smallest working baseline. [[axioms/A SIMPLE SYSTEM MAY OR MAY NOT WORK|Simplicity is not proof]], although [[axioms/SOME COMPLEX SYSTEMS ACTUALLY FUNCTION|complex function is possible]]. Require that [[axioms/A COMPLEX SYSTEM THAT WORKS IS INVARIABLY FOUND TO HAVE EVOLVED FROM A SIMPLE SYSTEM THAT WORKED|complexity grow from demonstrated simplicity]]. If complexity precedes function, [[axioms/A COMPLEX SYSTEM DESIGNED FROM SCRATCH NEVER WORKS AND CANNOT BE MADE TO WORK. YOU HAVE TO START OVER, BEGINNING WITH A WORKING SIMPLE SYSTEM|start again from a working simple system]].

Treat every expansion as a new system. Use [[axioms/THE STRUCTURE OF A MACHINE OR AN ORGANISM IS AN INDEX OF THE PERFORMANCE THAT MAY BE EXPECTED OF IT|structure to anticipate behavior]] without assuming [[axioms/FORM MAY FOLLOW FUNCTION, BUT DON’T COUNT ON IT|form proves function]]. Test because [[axioms/NEW STRUCTURE IMPLIES NEW FUNCTIONS|structure creates functions]], [[axioms/AS SYSTEMS EXPAND, NEW FUNCTIONS APPEAR SUDDENLY, IN STEPWISE FASHION|expansion creates discontinuities]], and [[axioms/AS SYSTEMS GROW IN SIZE AND COMPLEXITY, THEY TEND TO LOSE BASIC FUNCTIONS|growth can erase basics]]. Prefer that [[axioms/LOOSE SYSTEMS LAST LONGER AND FUNCTION BETTER|looseness preserves adaptation]]; [[axioms/BAD DESIGN CAN RARELY BE OVERCOME BY MORE DESIGN, WHETHER GOOD OR BAD|elaboration cannot rescue a bad premise]].

Before approval, define the exit. [[axioms/ALMOST ANYTHING IS EASIER TO GET INTO THAN OUT OF|Entry is easier than exit]], [[axioms/TAKING IT DOWN IS OFTEN MORE TEDIOUS THAN SETTING IT UP|removal may dominate setup]], and [[axioms/PLAN TO SCRAP THE FIRST SYSTEM YOU WILL ANYWAY|the first system needs a replacement path]]. Stop when [[axioms/SYSTEMS EXPAND, AND AS THEY EXPAND, THEY ENCROACH|growth consumes neighboring work]].
